# WHITEDOT

**Un pixel. Un mundo que suena.**

Un pixel blanco en un mundo negro. Cada día recorres un Camino corto. Al terminarlo se abre un Mundo que compone mientras lo exploras: 11 biomas, 33 hábitats, 52 géneros electrónicos y 28 linajes vivos de flora, fauna y construcciones. Todo lo que tocas suena a tiempo.

**Jugar:** https://whitedot-inky.vercel.app. En el teléfono puedes instalarlo como app (en iPhone: Compartir → Añadir a pantalla de inicio). Toca la pantalla una vez para activar el sonido.

## Cierre · fase 1 · identidades completas

`feat/cierre-f1-identidades` parte de `main 6702093`, que ya integra M1. Ocho gramáticas de paisaje unen contornos, espacio vacío, materiales, habitantes comunes y carácter musical: cauces, raíces, terrazas, órbitas, arrecifes, bóvedas, estratos e islas. Variantes deterministas, no ocho mapas cerrados ni nuevos géneros: permanecen los 11 biomas y 52 estilos.

**Saltar** favorece otra familia. El aviso de llegada y la Bitácora muestran su nombre. En **Menú → Prototipo → Laboratorio → Notas → Paisajes**, compara ocho lugares reales; siguen existiendo fuera del laboratorio. Hay 139 entradas/19 grupos, con notas anteriores conservadas. [Prueba en teléfono](PROBAR_UNIVERSO_VIVO.md).

El material guía trazo, paleta instrumental y filtros; el arreglo cambia articulación, aire y brillo conservando género, tempo, escala y batería. La fauna adapta su ritmo de movimiento; generar anatomías nuevas corresponde a F2. Terreno, rarezas anteriores, construcciones, coordenadas WD1 y progreso conservados. La proyección de habitantes comunes puede cambiar qué ejemplares ordinarios se ven.

[Plan de diez fases](PLAN_CIERRE_2.0.md): consolida las listas anteriores sin dar por terminados sus pendientes. Síntesis modular profunda, mezclas libres y respuesta musical más evidente de todos los objetos quedan en sus fases. [Verificación de F1](scripts/f1-validation.json): 81 suites Node, 14 recorridos afectados y 48 renders. Aceptación artística y rendimiento en teléfono físico pendientes.

## Fase musical M1 · integrada como base

`feat/m1-musical-identity` parte de `main 08d1833`. Añade 16 recetas versionadas de composición sobre los 52 géneros: cambia motivo, articulación, paleta, bajo, acentos, brillo, swing y espacios; conserva tempo, escala y batería nativa. No es todavía el motor de híbridos libres de M2.

Los 28 linajes vivos reciben un perfil individual estable al activarse: intención, cautela, curiosidad, paciencia, sociabilidad, actividad y preferencias musicales. Las plantas y construcciones expresan decisiones mediante apertura/resonancia; las tortugas pueden caminar despacio. El resto de las familias conserva su sistema anterior; el 100 % global y su aceptación perceptiva siguen en M5.

**Saltar**, visible en el Mundo durante esta etapa de práctica, busca otro lugar con contraste de género, receta y bioma y habitantes cercanos. **Menú → Volver al salto** recupera el punto anterior. Guarda progreso y dirección WD1, conserva favoritos y evita saltar durante grabaciones o escaneo. Los botones son silenciosos; la música sigue el destino.

Los territorios agrupan flora y fauna compatibles: una especie dominante, mezclas de dos o tres y cuatro densidades. Las bandadas comunes también favorecen especies locales. Se mantienen coordenadas del terreno, construcciones, ejemplares raros antiguos y progreso; las nuevas poblaciones usan semillas independientes. No sustituye todavía todos los sistemas ecológicos antiguos.

Hay ocho familias nuevas: pad analógico, teclas de fase, cristal FM, coro, cuerda resonante, bajo aterciopelado, aire granular y órgano orbital. Dieciséis programas originales añaden filtros móviles de paso bajo, banda y muesca; el paso bajo utiliza pendientes reales de 12/24/36/48 dB por octava. Gesto y clima modulan la apertura. Los bajos conservan filtros suaves; arcos pequeños señalan el filtro en su fuente. No contiene muestras ni presets comerciales.

Para comparar en teléfono: **Menú → Prototipo → Laboratorio → Notas → Música / Síntesis / Filtros**. El catálogo conserva las 91 entradas anteriores y añade 40: 16 lugares musicales reales, ocho instrumentos y 16 filtros (131 entradas, 18 grupos). Acerca el cubo al objeto; **Solo** permite escucharlo sin la pista. Las notas antiguas se conservan; la Bitácora registra instrumentos y programas escuchados. [Plan, alcance y pendientes](PLAN_MEZCLAS_MUSICALES.md) · [Verificación](scripts/m1-validation.json) · [Probar en teléfono](PROBAR_UNIVERSO_VIVO.md).

## Cómo se juega

1. **Camino.** Arrastra. Cada luz es una nota. Llena la barra del día.
2. **Mundo.** Se abre al completar el Camino. Tu linterna dura más con cada día de racha.
3. **Toca.** Lanzas un pulso. **Mantén.** Escuchas las voces cercanas. **Choca.** Lo dorado se puede tocar. **Quédate.** El lugar responde.
4. **Estudio.** Un secuenciador radial con los sonidos que recoges. También es tu campamento.
5. **Bitácora.** Lugares, formas, hallazgos raros, elementos, música y logros.
6. **Comparte.** Tarjetas 4:5 de tu día y sets grabados de hasta 60 s, listos para publicar.

Vuelve mañana. Creces. Simple.

## Correr local

```bash
python3 -m http.server 8000           # solo el juego
python3 server/app.py --port 8080     # juego + cuentas y duetos opcionales
```

No hay dependencias ni build. Los módulos necesitan HTTP; `file://` no funciona. En `localhost` o con `?dev=1` aparece el menú Prototipo. "Cuenta y duetos" solo aparece si responde el servidor opcional ([SERVIDOR_Y_DUETOS.md](SERVIDOR_Y_DUETOS.md)).

## Verificar

```bash
npm run audit:release   # integridad del shell, fuentes y enlaces
npm test                # suites de lógica (Node ≥ 18)
npm run test:browser    # recorridos de navegador y offline (Python + Playwright)
npm run test:audio      # mezclas renderizadas con Web Audio offline
python3 tests/server_api.py && python3 tests/duet_smoke.py   # servidor opcional
```

`CHROMIUM_PATH` indica el navegador si no está en el sistema. En ramas se ejecutan auditoría/lógica completas y navegador/audio enfocados en cambios. Antes de integrar/publicar `main`, se validan las suites completas una vez sobre el conjunto final. CI conserva los recorridos completos en cada PR, con navegador separado y audio repartido en tres grupos (`.github/workflows/checks.yml`); ver [AGENTS.md](AGENTS.md). Guía manual: [PROBAR_UNIVERSO_VIVO.md](PROBAR_UNIVERSO_VIVO.md).

## Publicar

El repo está conectado a Vercel (proyecto `whitedot`). Cada rama tiene vista previa; el merge a `main` publica producción. `vercel.json` fija Framework **Other** (`null`), Output Directory **`.`** y el build `node scripts/vercel-build.mjs`. El juego vive en la raíz: no genera `public`. La configuración del repo evita que Vercel busque esa carpeta inexistente. El build sella la revisión y la hora de publicación, que se ven al pie del menú. Vercel sirve solo la parte estática: el servidor de cuentas y duetos no corre ahí.

Flujo: una rama por fase de [PLAN_CIERRE_2.0.md](PLAN_CIERRE_2.0.md), desde main actualizado o desde la fase anterior pendiente de merge; commit y push. **Jay crea el PR y hace el merge.** [PLAN_2.0.md](PLAN_2.0.md) conserva los estados anteriores.
